# Architectural decisions

- **Rules in `core/` as RefCounted, never Node.** Enables headless tests today
  and a batch balance simulator later without scene scaffolding.
- **Stat paths + ModifierSet instead of per-entity upgrade fields.** One
  mechanism serves cards, permanent upgrades and future systems; effective
  value = (base + add) × mult, resolved at use time (no cache invalidation).
- **Small card-effect vocabulary (4 ops).** ADD_STAT covers projectile count
  and pierce as stats, avoiding a scripting language. Extend ops only when a
  card can't be expressed.
- **Stages generated by `tools/gen_stages.gd` into committed `.tres`.**
  Machine-written serialization avoids hand-maintained typed-array markup; the
  generator holds authored stage 1–2 definitions plus scaling formulas for
  3–30. Runtime only ever reads `.tres`.
- **No physics bodies for combat.** Distance checks over the enemy registry
  (≤ ~40 actors) are cheaper and deterministic; Area3D reserved for when real
  spatial queries are needed.
- **Seed streams via `DetRNG.derive(seed, salt, index)`.** Draft rolls are
  isolated per draft index, spawn X per run — consuming one stream can never
  desync another.
- **Enemy behavior is data, not subclasses.** `attack_interval` + `stop_range`
  express kamikaze / melee-boss / ranged with one script.
- **Camera/light rotations set in `battle.gd`,** not hand-written transform
  matrices in `.tscn` (error-prone to author/review as text).
- **Keyboard polling instead of InputMap actions** for the two prototype keys;
  serialized InputEventKey markup wasn't worth it yet. Revisit when real
  bindings/remapping arrive.
- **Smoke automation lives in the shipped autoload** behind `--smoke` user
  args with an isolated save file — the real game loop is what gets tested.
